# 分工與排期：五個官方插件同時開工

本文按代碼層次拆分全部工作。五個插件的邏輯層從第一天起同時開工，不用等畫布。各任務的細節見對應的說明文件，本文只講誰做什麼、按什麼順序做。

## 一、代碼分層

| 層 | 語言與位置 | 負責什麼 | 對應任務 |
| --- | --- | --- | --- |
| 宿主後端 | Rust，`spike/`、`src/` | 規則和數據：清單與輸出的解析、校驗和上限；綁定求值和重繪時間；設定類型；資源包；存儲導出 | A、B、C 的「後端」部分 |
| 宿主前端 | Rust/egui，`src/plugin_status_ui.rs` 等 | 畫出來、動起來、能點：畫布繪製、主題令牌、動畫、點按、懸停、滾動區、島仔節點、常駐小畫布、新設定控件 | A、B、C 的「前端」部分 |
| 投稿校驗 | Python，插件倉 `scripts/` | 讓新插件能通過投稿檢查 | P0 |
| 插件邏輯 | JavaScript，插件倉 `plugins/daozai.*/main.js` | 每個插件的數據、計算、狀態切換、存儲、提醒、常駐取值，用標準組件先出一個能用的版本 | P1–P5 第一階段 |
| 插件畫面 | JavaScript，同一個 `main.js` | 按設計稿生成畫布描述 | P1–P5 第二階段 |
| 數據 | JSON，插件包或 `src/` 數據文件 | 節假日數據、城市與時區對照表 | P5、C |

## 二、並行方式

```
第 1 周   A 畫布核心          P0 投稿校驗
          P1–P5 第一階段：邏輯層 + 標準組件版（五個同時做）
第 2 周   B 實時與交互        C 常駐、字體包、設定補項
          P1–P5 繼續邏輯層；A 合入後開始寫靜態畫面
第 3 周   P1–P5 第二階段：畫面層（五個同時做），B、C 合入後補動畫、點按、常駐小畫布
第 4 周   聯調、截圖對稿、驗收修改
```

建議人員：

- 一人負責宿主，順序做 A → B → C，也可以 B 和 C 兩人分做。
- 一人做 P0。
- 五個插件各一人，或者一人負責兩三個。

插件之間互不依賴，可以同時提交。

## 三、插件兩階段

### 第一階段：邏輯層（現在就能做）

只用現有 SDK，產出一個能裝能用的「標準組件版」。

1. 清單：ID、能力、設定、刷新、聯網來源、數據文件，按各插件說明填寫。暫時不聲明 `status.canvas`。
2. `main.js` 的邏輯部分，按「輸入 → 狀態 → 輸出」拆成純函數：
   - `computeState(input)`：從設定、存儲、時間、來源數據算出這一刻的業務狀態，比如工資的上班、休息、通關，或者金價的當前價、漲跌、區間點列。
   - `toStatus(state)`：用現有標準組件輸出 `status`，作為沒有畫布時的顯示。
   - `toPinned(state)`：常駐取值，先用現有 `text`、`value`、`icon` 寫法。
   - `toCanvas(state)`：第二階段再寫，現在先返回 `null`。
3. 存儲結構、設定遷移、提醒去重、`next_refresh_at`，全部在這一階段做完。
4. 測試：
   - 在插件目錄建 `fixtures/`，為每種狀態放一份模擬輸入 JSON。
   - 用 `daozai.exe --plugin-test plugin.json --input fixtures/xxx.json` 逐個跑，核對輸出。
   - 把命令和期望結果寫進插件目錄的 `TESTING.md`。
5. 交付：裝進島仔能顯示、能設定、能提醒的標準組件版，以及 fixtures 全部通過的記錄。

### 第二階段：畫面層（A 合入後開始）

1. 實現 `toCanvas(state)`，按設計稿生成畫布描述，清單加上 `status.canvas`。佈局裡放 `{"type":"canvas"}`，標準組件版的 `status` 保留，作為畫布出錯時的回退。
2. A 合入後先做靜態畫面；B 合入後補綁定、動畫、點按、滾動、島仔節點；C 合入後把常駐改成小畫布，並換上新設定類型。
3. 每完成一屏，和 `ui/` 裡的設計稿同尺寸截圖對比，差異寫進交付說明。

## 四、各插件的分層清單

| 插件 | 邏輯層要點 | 畫面層要點 | 依賴的新能力 |
| --- | --- | --- | --- |
| P1 便籤本 | 增刪改、完成和撤銷、置頂多條、搜索、常駐三種模式、專注事件、存儲容量提示 | 紙堆、分組列表、滾動、切換動畫、常駐色塊 | A、B（點按、滾動、過渡）、C（多行輸入、導出） |
| P2 現貨金價 | 兩個 xaus 來源、兩種單位各存點列、區間降採樣、提醒跨線去重、`fx_stale`、漲跌配色 | 主價格、漲跌塊、面積圖、提醒線、懸停讀數、單位和區間切換 | A、B（點按、`tips`、過渡）、C（常駐小畫布） |
| P3 實時工資 | 工作日數、多段休息、計薪規則、狀態切換時刻、跨午夜、常駐三種顯示 | 計價器翻動、經驗條、島仔節點、休息和通關動畫 | A、B（counter、progress、roll、loop、pet、burst）、C（常駐小畫布） |
| P4 世界時鐘 | 最多 10 個城市、時區偏移和夏令時、昨天/今天/明天、色條區段計算 | 錶盤、日夜換色、24 小時色條、現在線 | A、B（clock_angle、daylight、progress）、C（timezone 設定、常駐小畫布） |
| P5 日子 | 節假日數據與自己的日子合併排序、三種類型的天數、篩選、模板替換、整百天提醒 | 手撕日曆、撕頁動畫、車票滾動列表、常駐圖標和文字 | A、B（過渡、滾動、點按）、C（icon、color 設定、常駐小畫布） |

| 節點 | 交給誰 | 驗收什麼 |
| --- | --- | --- |
| A 完成 | 宿主負責人 | 演示插件靜態畫面、上限校驗、測試 |
| P0 完成 | P0 負責人 | 投稿腳本測試 |
| 五個插件第一階段完成 | 各插件負責人 | 標準組件版能裝能用，fixtures 全通過 |
| B、C 完成 | 宿主負責人 | 演示插件會動、能點；常駐小畫布；字體包；設定補項 |
| 五個插件第二階段完成 | 各插件負責人 | 截圖對稿、幀率記錄、全部測試 |
