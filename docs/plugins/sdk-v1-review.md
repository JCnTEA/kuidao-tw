# 島仔插件 SDK v1 需求覆蓋與待決定方案

2026-11-18 · 評審基線 `plugin-sdk-spike@dcf54db`

**建議第一輪用 QuickJS 做通本地插件的安裝、啟停、重啟和卸載。** 驗收的關鍵是作者能複製倒計時包、換一個 ID 和標題，再裝成第二個插件。兩個插件應各自有設定、開關和數據。現有樣例按引擎選定倒計時文件，宿主直接繪製倒計時文案，重啟讀回成功只能證明這個樣例可運行。這是從技術驗證走到通用 SDK 最先要跨過的一步。[載入實現](../../spike/mod.rs) · [卡片實現](../../spike/ui.rs) · [測量結果](runtime-spike.md)

## 需求覆蓋情況

“已實測”指 Windows 驗證程序已運行相應步驟。“草案”指已有接口或交互約定，仍需宿主實現。“缺接口”指按當前清單和示例，作者無法完成該步驟。瀏覽器原型可以核對入口和文案，真實進程的啟停、權限和數據恢復要在島仔裡另驗。需求來源見[功能建議模板](https://github.com/Renly1994/xiaotang-daozai/blob/main/.github/ISSUE_TEMPLATE/feature_request.yml)、[拓竹作者的樣例](https://github.com/Renly1994/xiaotang-daozai/issues/138#issuecomment-6919288370)、[SDK 草案](sdk-v1-design.md)和[插件清單格式](sdk-v1.schema.json)。

| 使用者需求 | 草案或樣例已覆蓋 | 作者接入時還缺什麼 |
| --- | --- | --- |
| 新增 AI 額度服務 | 草案有額度來源、週期和剩餘比例，沿用額度面板 | 用真實來源驗證授權、失效後重新登錄，以及停用時只撤回本來源 |
| 日程、農曆、紀念日 | 草案支援提供日程記錄，紀念日可以同時有自己的列表和固定卡 | “給某天加農曆標籤”與“新增一條日程”效果不同，前者缺少日期標註的公開約定。還要實測關日程僅撤回跨模塊輸出 |
| 信箱、聊天軟體 | 未讀數可用草案中的卡片，單次提示可用通知 | 寫入內置收件箱或消息列表缺來源接口。若要開放，先明確消息 ID、更新、撤回和已讀狀態由誰維護 |
| 查看列印機或其他設備 | 草案有臨時卡和獨立模塊。作者已在自己的分支接通本機監控 | 獨立頁缺少可組合佈局示例。本機監控提供只讀 HTTP，而當前 SDK 的網路規則拒絕本機地址，真實接入需另定授權 |
| 倒計時、從網站取數 | 已實測倒計時配置、顯示、存儲和重啟讀回。公開網站可按草案聲明 HTTPS 域名 | 倒計時缺按清單裝卸的完整驗證。網站請求只測過模擬傳輸，需用真實接口驗證。需要登錄的網站還缺作者可調用的憑據使用約定 |
| 皮膚、表情、圖標 | 草案允許無代碼資源包，使用者從原選擇器切換 | 資源路徑能寫進清單，具體可替換部位、表情幀與缺失素材回退還需一個可安裝的樣例 |
| 歌詞、天氣、待辦來源 | 歌詞有曲目標識和時間字段。天氣和待辦已有設定歸屬可選 | 實時歌詞需驗證切歌時清除過期數據。清單尚無天氣或待辦來源能力，進入原面板需要對應的數據約定 |
| 專注日誌、快捷操作 | 草案有專注結束事件，原型覆蓋手動和自動記錄 | 驗證同一事件只記錄一次、關閉自動記錄仍可手動使用、停用後遲到的回調不寫入 |
| 便籤等獨立工具 | 草案有列表、詳情、編輯表單和私有存儲 | 用實際數據驗證編輯、固定、卸載保留和重裝認領。使用者想專門查看完整狀態時，也需要有進入獨立頁的途徑 |
| 改進內置體驗 | 例如調整剪貼板歷史條數，由本體擁有設定和執行邏輯 | 放在原設定中即可。如插件要提供新的剪貼板來源，再單獨討論它能讀寫哪些內容 |

## 第一輪的四個驗收場景

| 場景與現狀 | 使用者或作者怎樣操作 | 通過條件 |
| --- | --- | --- |
| 發薪倒計時 · 樣例部分已實測，首個完整實現 | 本地選包載入，在「我的插件」點“前往設定”，去「待辦與置物」改日期。停用後重啟，再啟用。分別試卸載保留和刪除後重裝 | 改日期後島卡更新。停用後刷新調用數停止增長，重啟仍停用。啟用恢復原日期。卸載後入口和卡片撤下，同身份重裝按上一次的保留選擇恢復或使用預設值 |
| 換膚包 · 交互已有原型 | 從奶油切到插件皮膚，把膠囊改為劉海，先切回內置皮膚，再試停用正在使用的插件皮膚 | 已安裝的皮膚可隨時切換。停用後顯示奶油＋劉海，包內配色隨各自皮膚儲存 |
| 紀念日 · 開關模型已有推演 | 建一條紀念日，同時固定倒數、顯示在日曆。先關日程，再關紀念日，重開時核對原選擇 | 關日程只撤下日曆記錄。關紀念日時「我的插件」同步顯示停用，入口和全部輸出撤下。重啟用後原文、日期、固定選擇均可找回 |
| 拓竹 · 作者已有參考實現，SDK 接入待驗 | 先用模擬數據讓作者加一個“預計完成時間”，再用已授權的本機監控驗證正常、暫停告警、設備離線、監控沒啟動和停用 | 第一步只更新插件包，島仔無需重新編譯。第二步能區分舊數據與當前值，依賴離線時降低重試頻率，設備告警顯示給使用者。關閉模塊後島仔停止讀取，使用者原有監控程序獨立運行 |

四項共同遵守已討論的入口規則。參數在唯一歸屬設定頁調整，「我的插件」統一提供啟停、卸載和跳轉。頁面管理負責模塊啟停。倒計時掛在已有模塊，僅用插件開關就能單獨停用它。

## 需要決定的三件事

**1. 下一輪用哪種運行環境？建議先選 QuickJS 驗收本地插件。** 作者改日期算法後可直接載入腳本，使用者繼續從待辦設定改發薪日期。採用現有 Rust 邏輯較多的作者也可從 WASM 獲益。實測中兩者載入十個實例的熱中位數分別為 12.28 和 4.12 毫秒，程序分別增加 0.152 和 1.163 MiB。雙環境首發需要維護兩套執行與兼容迴歸。當前只需決定倒計時完整流程用哪套，公開支援哪些語言可等作者試接後定。[完整實測](runtime-spike.md)

**2. 作者能自己設計到什麼程度？建議先試“作者組合佈局，島仔渲染”。** 原額度頁由作者提供數據，島仔沿用原面板。獨立頁允許作者決定字段、順序、分組和點擊動作。例如作者把預計完成時間放到進度下方，使用者換皮膚或縮放後仍能看清並點擊。固定模板容易起步，但每次超出模板都需要島仔新增樣式。開放自由繪製能容納特殊視覺，也需要作者處理主題、縮放和命中區域。先用拓竹的只讀頁和便籤的編輯頁各試一次佈局組合，再定公開控件範圍。

**3. 是否允許插件讀取已安裝軟體提供的狀態？建議單獨試驗“使用者指定應用、只讀授權”。** 一條路是沿用使用者選文件的草案，讓監控工具導出狀態。另一條是適配已有的本機只讀服務，拓竹作者可複用現成監控。第二條需由島仔核對服務身份、處理端口變化及本機代理，在安裝前說明依賴，首次啟用時寫明“允許讀取拓竹列印監控的狀態”。撤權後停止讀取。該選擇影響真實設備接入，倒計時和模擬列印頁可獨立驗收。

## 本地安裝流程的交付邊界

首個可試用版本應能從開發者模式選擇本地包、讀取清單、註冊設定和島卡，再從「我的插件」啟停或卸載。驗收時用兩個不同 ID 的倒計時包分別改日期和停用，確認彼此獨立。還要在上級模塊關閉後重開，確認此前手動停用的插件保持停用。

等這條流程可試用，再依據實測區分穩定與實驗能力。舊包兼容期限、市場審核和簽名分發可在對外發布前決定，首輪本地安裝驗收使用本地樣例包。
