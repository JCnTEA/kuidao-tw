藍牙電量沒有一個萬能接口。

島仔適合採用「Windows 已有電量 + 標準 BLE 電量 + 按設備補充協議」的組合。高星項目能提供成熟的讀取與狀態處理思路，但跨品牌適配必須落實到具體型號和連接方式。

星數與最近推送日期來自 GitHub 當日倉庫元數據；覆蓋範圍根據 README 和所列源碼核驗。源碼存在不代表本機已完成硬件驗證，推送日期也不等於穩定版發佈日期。

源碼裡的關鍵結論

通用 BLE：讀取一次，再訂閱變化

標準電池服務使用 0x180F，電量特徵使用 0x2A19。先確認設備確實提供服務，再讀取 0–100 的值；支持 Notify/Indicate 才訂閱。不支持通知時使用低頻讀取。Bleak 的 WinRT 後端還處理服務緩存、會話關閉、連接失敗和回調清理。Windows 官方文檔明確 GATT 訪問可能等待較長時間，不能讓它阻塞界面。

來源：Bleak · WinRT client、btleplug · Windows peripheral、BLE Battery Service 實現、Microsoft GATT Client。

羅技：同一個品牌也有多套電量語義

Solaar 的 get_battery 探測多個能力，分別處理 battery status、unified battery、voltage 和 Centurion。部分結果是百分比，部分是粗分檔，部分由電壓估算。島仔的數據模型應保留「精確百分比 / 約值 / 檔位」區別，不能全部轉換成看似精確的百分數。

來源：hidpp20.py · get_battery / decipher_battery_* / estimate_battery_level_percentage。

真無線耳機：左右耳、盒子、充電狀態分開建模

GalaxyBudsClient 的 StatusUpdateDecoder 對不同代際分支，分別讀取 BatteryL、BatteryR、BatteryCase；充電位受設備能力限制。OpenPods 從 Apple 廣播半字節提取分檔電量，並處理左右交換；其標記值 15 不是 15% 電量。廣播出現不等於設備已與本機連接，也不能僅憑同名或信號最強就合併到已配對設備。

來源：StatusUpdateDecoder.cs、PodsStatus.java、PodsStatusScanCallback.java。

2.4G 無線：接收器在線不代表耳機在線

HeadsetControl 根據 VID/PID 選擇設備實現。適配要再檢查設備是否可用、報文返回是否代表有效電量，以及型號的平台支持。其設備表按能力列示支持情況，不能只看到某個型號就默認所有功能可用。

來源：device_registry.cpp、逐型號能力與平台支持表。

一個相關但不宜作為首選依據的項目

Kaandonmez/BluetoothBatteryMonitor：★ 2，MIT，最近推送 2026-09-06。README 宣稱支持 36 類協議。已檢查的 src/BluetoothBatteryMonitor/Services/BluetoothBatteryAggregatorService.cs 實際接入 Windows PnP、BLE GATT、Apple 廣播、Logitech HID 四個 provider，可以參考其分層結構，但本次沒有逐一核實全部 36 類協議及設備實測。因此不把宣傳覆蓋數當作可直接承諾的兼容數量。

來源：聚合服務源碼。另一個 muedsa/BluetoothLEBatteryMonitor 已標記 Deprecated，其關於 GATT 不能解決所有經典藍牙耳機電量的說明仍有參考意義。

島仔已有基礎與適配建議

基於主工程提交 6156474：src/bt.rs 已枚舉連接中的經典藍牙與 BLE 設備，使用 Windows PnP 屬性 {104EA319-6EE2-4701-BD47-8DDBF425BBE5}, pid 2 讀取電量。連接檢查約每 2 秒一次，電量約每 60 秒讀取，設備變化時提前刷新。已有設備類型、緩存和退出信號，可繼續複用。

src/app.rs::sync_device 主要負責連接/斷開提醒；src/extras.rs 已有設備圖標。原始電量只有 Option<u8>。當前分支補充來源、讀取時間、連接狀態與去重，監控和連接通知分別控制；通用讀取不推斷充電狀態或分體電池。

首版：Windows + 標準 BLE

保留 PnP 電量路徑，補充 GATT Battery Service。後台每 2 秒檢查連接、每 60 秒刷新電量，連接變化時提前讀取；慢速 GATT 請求獨立運行。沒有電量的設備保留連接狀態。後續可引入 DeviceWatcher 與特徵通知減少輪詢。

擴展：逐類補充設備

優先針對實際使用的設備補齊：羅技 HID++、Galaxy Buds RFCOMM、Apple 廣播、遊戲耳機 USB HID。每類標註連接方式與實測型號，不宣稱全品牌支持。

事件監聽依據：Microsoft DeviceWatcher。此分支現已接入 Windows PnP 與標準 BLE 兩條讀取路徑，按設備身份合併，並保留來源、讀取時間與連接代次。廠商協議仍是後續適配方向。

界面與數據必須一致

  • 每個電池分量保留數值、精度、來源、採樣時間與可選充電狀態；有效的 0% 與未上報嚴格區分。
  • 連接狀態與讀數新鮮度分離。斷開顯示「已斷開 · 上次讀數」，過期顯示「待更新」，未知顯示「—」。
  • 同一物理設備的多個 Windows 節點按穩定設備身份合併；不按名稱合併，不讓一個來源的空值覆蓋另一個來源的新鮮有效值。
  • 通用 BLE 電量特徵只提供電量；沒有設備證據時不推斷充電、耳機盒電量或剩餘可用時長。
  • 建議低電量提醒按閾值越界觸發一次；恢復到閾值上方一定幅度後才重新允許提醒。過期、斷開或正在充電的讀數不觸發。
  • 常駐最多兩台，可從設備卡片固定優先顯示；未固定時優先顯示低電量設備。其餘設備在展開卡片中查看。
